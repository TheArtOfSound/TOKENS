## What is still missing, and why it is not code

Technical SEO is not the bottleneck. Two things are, and neither can be fixed
from inside this repo:

### 1. Nothing links here

Checked on 2026-07-24: `imagineqira.com` contains **zero** links to
`ledger.imagineqira.com`. A site with no inbound links from an already-indexed
site is very slow to get discovered, no matter how clean its markup is.

Added this session: `oortstack.com` now links here sitewide from its footer
(committed in the Oort repo — **not deployed**; it ships via the Docker/Caddy
step in that repo's `DEPLOY.md`).

Still needed, highest value first:

**a. imagineqira.com** — the main site is already indexed, so this is the single
most valuable link. Its source is not on this Mac (Cloudflare-hosted, no local
repo found), so it has to be added wherever that site is edited:

```html
<a href="https://ledger.imagineqira.com">Ledger</a> —
verifiable evidence for AI-assisted work.
```

**b. flows.oortstack.com** — live, built on Emergent, no local source. Same
snippet, added through the Emergent editor.

Keep these as plain links. Do **not** add `rel="nofollow"`; these are genuine
same-owner links and nofollow would waste them.

### 2. Google does not know the site exists

The Chrome extension was not connected this session, so Search Console could not
be reached from here. This is a five-minute manual step:

1. Open [Search Console](https://search.google.com/search-console).
2. If a **Domain** property for `imagineqira.com` already exists, the subdomain
   is already covered — skip to step 4.
3. Otherwise add a **URL prefix** property for `https://ledger.imagineqira.com`.
   Verification will offer an HTML file or a meta tag; either works. Drop an HTML
   file into `public/` and it ships on the next build, or paste the meta tag into
   `index.html`.
4. **Sitemaps** → submit `sitemap.xml`.
5. **URL Inspection** → enter `https://ledger.imagineqira.com/` → *Request
   indexing*. Repeat for `/people` and `/employer`. This is what actually starts
   the crawl; the sitemap alone can sit unread for weeks.

Bing Webmaster Tools can import the Search Console property in one click once
step 4 is done.

## What was deliberately not done

**No `aggregateRating`, no scores, and no invented job titles in the structured
data.** This is the one place where overclaiming is worst: search engines lift
these fields out of context and show them as fact in results, where the reader
never sees the qualifications the page itself puts on them. A star rating in
JSON-LD would be exactly the universal score this product refuses to compute —
and it would be the one claim users never get to correct.

The generator emits only fields the signed snapshot supports. If a member has no
location, the field is omitted rather than guessed.

**No keyword-stuffed landing pages and no directory-submission spam.** With one
member in the directory, more thin pages would make indexing worse, not better.
The fix for thin content is more members, not more pages.
